# OpenCitations API — agent reference

A digest of the two OpenCitations REST APIs, written for an agent. Everything
here was verified against the live services; measurements are dated
**2026-08-12**. OpenCitations publishes no `llm.txt`, hence this snapshot.

- Meta v1.1.1 — `https://api.opencitations.net/meta/v1` — bibliographic metadata
- Index v2.2.0 — `https://api.opencitations.net/index/v2` — citation entities

Both are generated by RAMOSE over SPARQL endpoints. Data is CC0.

## The one thing to know first

**There is no search operation.** No endpoint accepts a query string, a topic, a
title, a year or an author name in free text. `/meta/v1/search` returns 404.
Every operation starts from an identifier you already hold. Find works with a
search engine (OpenAlex, HAL, Crossref); use OpenCitations to explain their
citations.

## Identifiers

| Prefix | Where it is accepted |
|---|---|
| `doi:` | Meta `/metadata`, Index counts and lists |
| `pmid:` | Meta `/metadata`, Index counts and lists |
| `omid:` | everywhere — `omid:br/…` for a work, `omid:ra/…` for an agent |
| `pmcid:`, `isbn:`, `openalex:` | Meta `/metadata` only |
| `issn:` | Meta `/metadata` (returns the journal), Index `/venue-citation-count` |
| `orcid:` | Meta `/author`, `/editor` |

- DOIs are **case-insensitive**.
- `doi:`, `pmid:` and `omid:` for the same work return **identical** citation
  sets (verified on a 3-edge work).
- **OMID** = OpenCitations Meta Identifier, the internal entity id.
  **OCI** = Open Citation Identifier, the id of one citation edge, shaped
  `<citing-omid-local>-<cited-omid-local>`.

## Meta v1

| Path | Returns |
|---|---|
| `/metadata/{ids}` | one record per identifier; join several with `__` |
| `/author/{id}` | every work of an ORCID (or `omid:ra/…`) as author |
| `/editor/{id}` | idem, as editor |

Fields, **all flat strings**: `id`, `title`, `author`, `pub_date`, `issue`,
`volume`, `venue`, `page`, `type`, `publisher`, `editor`.

Encodings to parse:

```text
id        "doi:10.1108/jd-12-2013-0166 omid:br/06180334099 openalex:W1977728350"
author    "Peroni, Silvio [orcid:0000-0003-0530-4305 omid:ra/0611]; Shotton, David [omid:ra/0612]"
venue     "Journal Of Documentation [issn:0022-0418 omid:br/06201057]"
pub_date  "1989", "1989-09" or "1989-09-24" — precision varies by record
```

`type` values seen: `journal article`, `book`, `book chapter`, `dataset`,
`proceedings article`, `report`, `web content`.

There is **no abstract field** and no full-text link. If a task needs either,
OpenCitations is the wrong source.

## Index v2

| Path | Returns |
|---|---|
| `/citation-count/{id}` | `[{"count": "57"}]` — incoming citations |
| `/reference-count/{id}` | `[{"count": "45"}]` — outgoing references |
| `/venue-citation-count/{issn}` | citations received by a journal |
| `/citations/{id}` | every incoming edge |
| `/references/{id}` | every outgoing edge |
| `/citation/{oci}` | one edge, by its OCI, **without** the `oci:` prefix |

Edge fields: `oci`, `citing`, `cited`, `creation`, `timespan`, `journal_sc`,
`author_sc`.

- `creation` is the publication date of the **citing** work.
- `timespan` is ISO 8601 `PnYnMnD`, and can be **negative** (`-P1Y0M2D`) when
  the cited work is dated after the citing one.
- `journal_sc` / `author_sc` are `"yes"` / `"no"`: journal and author
  self-citation. Both must be checked to exclude self-citations.

`/citation/{oci}` is redundant for most tasks: the complete edge is already in
every `/citations` and `/references` row.

## Query parameters (RAMOSE, both APIs)

| Parameter | Form | Verdict |
|---|---|---|
| `require` | `require=field` | drops rows with an empty field |
| `filter` | `filter=field:=value`, `:<`, `:>`, otherwise regex | **avoid** — see below |
| `sort` | `sort=asc(field)` / `desc(field)` | works, but only after the whole set is computed |
| `format` | `format=csv` or `json` | CSV is ~2.6× smaller |
| `json` | `json=array("sep",field)` / `dict("sep",field,f1,f2)` | reshapes the payload |

**`filter` is a trap at scale.** Pushed server-side it cost 67–78 s and returned
**truncated, invalid JSON** on repeated runs (354 424 then 1 056 965 bytes).
`filter`+`sort` together yielded 4 891 rows / 1.95 MB. Filter and sort on the
client instead.

The documented `[index name] =>` value prefixes do **not** appear in live
output.

## Volume: the real constraint

There is **no pagination and no `limit` parameter**. A list endpoint returns the
entire set in one response.

| Case | Measured |
|---|---|
| `/citations/` on a 24 354-citation work | 9.93 MB in 0.72 s |
| the same, `format=csv` | 3.74 MB |
| a 217-citation work | 81 517 bytes |
| a 57-citation work | 57 rows, instant |

And the failures:

- `citation-count/doi:10.1038/nature14539` → **HTTP 500 after 244 s**
- `/citations/` on that work → no answer in 5 minutes
- `citation-count` on another very large work → timeout at 45 s once, fine later

Practical rule: **call the count endpoint first**. It is cheap and it tells you
whether the list is retrievable at all. Above a few thousand edges, report the
count and stop.

## Truncation with HTTP 200

`/author/orcid:0000-0003-0530-4305` returned 45 945 bytes of **invalid JSON**
once, then 111 030 bytes and 125 valid rows on the three following attempts. The
status code alone does not mean success: parse defensively and retry a parse
failure once.

## Authentication, quotas, caching

- No header at all → works. The APIs are fully public.
- A token goes in a raw `authorization` header, with **no scheme prefix**.
- An invalid token → **HTTP 403 with a plain-text body**, not JSON.
- Rate limit: **180 requests/minute per IP**.
- Varnish + Redis in front; an `age` header of 707 543 s was observed, so counts
  can be days stale.

## Quirks worth remembering

- `metadata/issn:0138-9130` returns **57 duplicate rows of the journal itself**,
  not its articles. An ISSN is not a listing key; there is no way to enumerate a
  journal's works.
- An **unknown identifier is HTTP 200**: `[{"count":"0"}]` or `[]`. Absence and
  zero are indistinguishable at the protocol level.
- `/index/v2/citations/issn:…` and `/index/v2/metadata/…` → 404 in plain text.
  Meta paths are not Index paths.
- How many identifiers `/metadata/{ids}` accepts in one `__`-joined call is
  undocumented; 2 are confirmed, and the only apparent bound is URL length.
  Batching by 10 is safe.
